# walletscrutiny verification — Cypher Box

This folder lets anyone check that the Cypher Box APK Google Play serves was
built from this public source. It implements the
[walletscrutiny](https://walletscrutiny.com/) verification contract.

> Note on naming: walletscrutiny moved from a per-app `test.sh` to a `build.sh`
> that emits `COMPARISON_RESULTS.yaml`. The security plan (§11.2) predates that
> change and says "`test.sh`"; this folder follows the **current** `build.sh`
> spec so a verdict is submittable.

## What it does

Cypher Box ships on Google Play as an **AAB**. Play re-signs it with Google's
app-signing key (Play App Signing) and serves **per-device split APKs**, so the
served bytes are never identical to a locally signed build. `build.sh`:

1. Rebuilds the **unsigned** release AAB deterministically in the pinned
   [`Dockerfile.build`](../Dockerfile.build) image (same toolchain as
   `make repro-build`), and prints its SHA-256.
2. Derives a **universal APK** from that AAB with a sha256-pinned bundletool.
3. Compares every entry the Play binary serves against that universal APK,
   ignoring the v2/v3 signing block, `META-INF` signature files, Play's
   stamp-cert, and zip compression (per walletscrutiny: *"unzip and compare —
   the diff is only in the compression"*).

Result: `COMPARISON_RESULTS.yaml` with `verdict: reproducible | not_reproducible | ftbfs`.

## Usage

Requirement: **docker or podman only** (no sudo, no `make`, no host JDK/SDK/node).

```sh
# 1. Pull the installed APK(s) off a device that has the Play build:
adb shell pm path io.cypherbox.btc            # lists base.apk + split*.apk paths
mkdir play-apks && for p in $(adb shell pm path io.cypherbox.btc | sed 's/package://'); do adb pull "$p" play-apks/; done

# 2. Check out the git tag matching that build's versionName, then:
./walletscrutiny/build.sh --binary ./play-apks --version 0.1.0 --arch arm64-v8a --type bitcoin
cat walletscrutiny/COMPARISON_RESULTS.yaml
```

`--binary` may be a single APK or a directory of split APKs (the base APK is
compared; config splits are generated by Google from the same AAB).

## Inlined config inputs (bark token, relay key, .env)

The app compiles three config values into the binary at build time:

| Value | File (gitignored) | Lands in | Placeholder effect |
|---|---|---|---|
| Second.tech bark access token | `src/services/ark/secrets.ts` | JS bundle | Ark cannot authenticate to the token-gated mainnet server |
| Push-relay API key | `blue_modules/secrets.ts` | JS bundle | push-notification relay registration disabled |
| `GOOGLE_WEB_CLIENT_ID` | `.env` | BuildConfig | Google Drive backup disabled |

Fresh clones build with the committed `.example` placeholders automatically,
so the build always completes and toolchain determinism is verifiable with no
secrets at all (`make repro-verify`).

To produce a **functional** audit build (Ark actually talks to the mainnet
server), insert your own token before building:

```sh
cp src/services/ark/secrets.example.ts src/services/ark/secrets.ts
# paste the access token Second.tech provides on request (see the file header)
```

The relay key and web client ID placeholders do not affect Ark.

**Verdict semantics:** a `reproducible` verdict against the Play binary
requires rebuilding with the *same* inlined values production used. A build
with your own token reproduces everything *except* those constants — expect
`assets/index.android.bundle` to differ by exactly the inlined config. The
script's notes record which inputs came from `.example` placeholders vs
provided files, so a bundle-only diff is attributable.

## Status / known limitation (read before trusting a verdict)

**Not yet validated end-to-end** — authored without a Docker host or a real Play
download. Before this is the canonical verifier, run it once on a Docker host
against a genuine Play build and confirm the verdict.

The hard part is AAB verification: bundletool's *universal* APK carries every
split's content and a **superset `resources.arsc`**, while Play serves a
*filtered* base/split. `build.sh` compares in the **Play → built** direction
(every served entry must be reproducible; universal-only extras are expected)
and flags a `resources.arsc`-only difference separately, because that one needs
confirming by building the matching split (`bundletool --mode=default` + a
device spec) rather than the universal APK. Refine here once validated.
